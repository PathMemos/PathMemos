# 0018: OSS 用户图片开启版本化——对象数据保留与防删策略

日期：2026-10-09

## 状态

已接受

## 背景

用户图片是全系统唯一不可再生的用户数据（01 §2 O1「记录留存」），但长期处于备份/灾备体系之外：数据库有逐小时备份与离机副本（ADR-0015），OSS 对象无版本化、无回收站——一次 `DeleteObject` 即永久丢失；bucket 创建凭证与应用同机存放，误删与凭证泄露式破坏均不可逆。DEPLOYMENT §5 已登记该边界；数据保留与防删策略的取舍由本 ADR 声明。

## 决策

1. **bucket 一律开启版本化**：deploy.sh 的 OSS 预检阶段对新建与存量 bucket 幂等调用 `PutBucketVersioning`（状态不为 Enabled 即置为 Enabled）。开源版自建 bucket 由部署者按本 ADR 自行开启（README 提示）。
2. **跨区复制、定期对象清单备份不做**：成本与复杂度与当前规模不成比例；版本化已把「一次误删即永久丢失」变为「需逐版本枚举删除」的故意行为，对误删/误覆盖是完备解。
3. **已接受残余**：同机凭证泄露者理论上仍可逐版本删除全部历史（版本化抬高破坏门槛但不抵御持有合法凭证的故意破坏）——与 ADR-0007（API Key 明文）同类的同机信任边界取舍。

## 后果

- 误删/误覆盖（含应用层 bug、人工误操作）可从非当前版本恢复；主要风险场景闭合。
- 版本累积量级：文件为 UUID 定名、原位覆盖极少（仅 `SaveSystemWithName` 确定性命名会覆盖），非当前版本近乎不产生；存储成本增量可忽略。
- 可选的未来策略（现在不实施）：为非当前版本配置 lifecycle 过期（如 90 天）以封顶极端场景下的存储增长——实施前提是出现实际版本堆积的观测证据。
- 恢复路径：阿里云控制台或 `ossutil` 按对象枚举历史版本回拷；无需应用侧改动。
