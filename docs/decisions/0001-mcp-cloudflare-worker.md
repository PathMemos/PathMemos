# 0001: MCP 协议层剥离到 Cloudflare Worker

- 状态：已接受
- 日期：2026-07
- 取代：无

## 背景

源站为单台 4C8G 云服务器。MCP 客户端流量会带来连接保持、TLS 与协议解析开销；同时希望隐藏源站 IP 并降低源站负载。Cloudflare 的 workers.dev 域名在国内不可达。

## 决策

**我决定**：MCP 公网入口统一由 Cloudflare Worker（`mcp.pathmemos.com`）承担，源站只暴露受共享密钥保护的 `/internal/mcp/*`，不再注册公开 `/mcp/*` 协议端点。

## 备选方案

- 源站直接暴露 `/mcp/*`：否决——暴露源站 IP、占用源站连接与解析资源、无边缘缓存与平台限流。
- 引入第三方 API 网关：否决——额外依赖与运维成本，且已有 Cloudflare 可用。

## 后果

### 正面

- 隐藏源站 IP，获得全球边缘接入与边缘缓存/限流。
- 源站连接与协议解析开销下降。

### 负面 / 代价

- SaaS 的 MCP 功能**强依赖 Cloudflare Worker + KV**，单机不再自足。
- 源站必须维护 `MCP_WORKER_SECRET`，saas 模式缺省时启动即失败；源站保留空值 500 防御分支（启动校验通过后不可达）。
- 开源版走另一条路径（直接暴露 `/mcp/*`），两形态行为需在文档中区分。
