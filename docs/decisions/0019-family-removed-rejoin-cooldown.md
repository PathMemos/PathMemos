# ADR-0019：家庭移除冷却（removed_members）

- 状态：已接受
- 日期：2026-10-09
- 关联：ADR-0010（开放家庭邀请链接）、ADR-0017（家庭加入暴露个人历史）、02d §3/§5

## 背景与决策

家庭邀请链接 `linkId = familyId` 永久有效、加入无需确认（ADR-0010），「owner 可移除成员」不构成访问终止——被移除者持链接可**立即、无限次重新加入**，每次加入即重新获得家庭当前日记视图（含自动记录的位置轨迹），且 owner 对加入无任何感知——对一个承载家庭成员位置数据的产品，敌意方（如离异配偶）可静默循环重入。

决策：**移除冷却**。`families.removed_members`（jsonb，`{userID: 移除时间 RFC3339}`）记录被 owner 移出的成员；`/family/invite-link/join` 事务内检查，任一加入者（含 owner 整家合并路径的全部被迁移成员）处于目标家庭移除时间起的 **7 天**冷却期内 → 403 `REMOVED_REJOIN_COOLDOWN`。

## 实现要点

- 冷却检查在 `JoinFamily` 事务内执行（`family/service.go` `checkRejoinCooldown`）：直接加入检查发起者；`isOwnerOfSource` 合并路径检查全部被迁移成员（防经第三方家庭整家合并走私冷却名单）。
- 再次移除同一个人时 jsonb merge 覆写时间戳，冷却期重新起算（有意语义：惯犯每次被移除都重置时钟）。
- 迁移 000014 为纯 expand（加列带默认值），旧代码不受影响。
- 前端按 biz_code 映射三语文案（「你近期被移出该家庭，稍后再试」），join 业务失败统一清除 `pendingLinkId` 的既有逻辑终止循环跳转。

## 后果与已接受残余

- **误操作恢复**：owner 手滑移除家人后，7 天内无提前解锁通道（邀请链接是唯一加入通道、不轮换）——家人等待 7 天后可重新加入。若该 UX 痛点实际出现，出路是调小冷却常量，而非新建重新邀请通道。
- **持续滥用的终局手段**：解散重建家庭即事实上的链接轮换（新 familyId 使旧链接永久失效），成本是全员散回个人家庭、owner 重建重分享。
- **换微信小号重入不设防**：冷却按 userID 记录；小号是新 userID，拦截需 ADR-0010 已否决的邀请令牌表。小号重入仍受 6 人上限约束、且以陌生成员身份出现在成员列表（可见），符合既有信任模型。
- 冷却本质是速率限制而非访问控制；防御力来自「每次重入产生可见的成员列表变化（joinedAt 刷新）」+「每次移除重置时钟」的组合。
