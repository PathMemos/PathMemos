# 0013 已删除图片的边缘缓存定期批量收敛

日期：2026-09-16｜状态：已接受

## 背景

图片使用公开 URL + OSS `Cache-Control: max-age=31536000, immutable`（02g F-6）；物理删除是异步且周期性的（孤儿清理 7 天）。两者叠加意味着：文件删除后，其 URL 在 CDN/客户端缓存中最长一年仍可命中——「已删除即不可达」在缓存维度不成立。隐私后果：**已删除图片必须最终不可达（含边缘缓存），但不引入删除即清缓存的同步开销，采用定期批量处理**。

## 决策

1. **目标**：已删除（物理删除完成）的图片，其 URL 在边缘缓存中最终不可达；允许一个有限的收敛窗口。
2. **机制**：**定期批量清理**——复用/扩展现有周期任务体系（如孤儿文件清理或新增低频任务），对已删除对象执行 OSS/CDN 缓存刷新（purge），批次限速以不影响主业务为准。不做逐次删除同步 purge。
3. **不动 immutable 写入策略**：上传仍写一年 immutable（读性能与回源成本优先）；可达性收敛由删除侧批量清理保证。

## 落地状态

**已实现**：`internal/purge` 队列 + CDN 刷新客户端、`Storage.DeleteFile` 删除钩子、后台任务 `purge_deleted_objects`（默认 24h，单轮 ≤1 万 URL，失败整批回退）。开关 `CDN_REFRESH_ENABLED`（默认关闭）；未配置/未开启时行为与实现前一致（删除仍即时生效于源站，边缘缓存靠 TTL 自然过期）。残余边界：客户端本地已缓存的副本无法服务端强制失效。
