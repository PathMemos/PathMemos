# 0007: MCP API Key 明文存储与永久展示

- 状态：已接受
- 日期：2026-09
- 取代：无

## 背景

产品要求用户可随时在小程序查看已生成的 API Key（永久展示）；认证侧已使用 SHA-256 `key_hash` 查询，不依赖明文列。

## 决策

**我决定**：`api_keys` 同时存明文（`api_key`，供展示）与 SHA-256（`key_hash`，供认证）；Key 永不过期（`expires_at` 固定 9999 占位、认证不校验）。

## 备选方案

- 只存哈希、Key 仅创建时一次性展示：否决——违背「永久展示」的产品需求，丢失成本高。
- 明文列加密存储：否决——密钥仍在同一部署环境，收益有限、复杂度上升。

## 后果

### 正面

- 满足「随时可查」需求；认证只走 hash 列。

### 负面 / 代价

- DB 泄露即全量 Key 泄露。缓解：一用户一键、提供 rotate/delete、注销级联删除、Key 作用域仅日记/回忆读写且 30/min 限流。
- Key 明文副本经绑定 token 存于 Cloudflare KV（`mcp_token:<token>` → apiKey，30 天 TTL 自清）——泄露面扩展至第三方平台；rotate/注销不联动清理该副本（残留仅指向已失效 Key，回源 401，无数据风险），按需经 `DELETE /worker/register` 或 KV 手动清理（详见 02h §8.2 已知取舍）。
